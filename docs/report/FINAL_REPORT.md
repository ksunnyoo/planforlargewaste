## 1. 문제와 사용자

**대상**: 이사·정리 업체의 견적·상담 담당자.
**상황**: 고객이 버릴 물건 목록을 보내면, 담당자가 해당 지자체의 대형폐기물 품목명·규격·수수료·신고 절차를 찾아 안내합니다.

현재 방식의 한계는 다음과 같습니다.
1. 고객 표현("3인용 소파", "책상")과 지자체 공식 품목명·규격이 달라 일일이 대조해야 합니다.
2. 지자체마다 신고·배출 방식이 달라 안내문을 매번 찾아 읽어야 합니다.
3. 지자체 수수료와 업체 작업비가 섞여 설명되면 고객이 총비용을 오해할 수 있습니다.
4. 안내가 틀리면 고객 항의와 재작업으로 이어집니다 **[가설]**.

이 서비스는 **업체 담당자가 견적과 안내를 준비하는 도구**이며, 배출 신고를 대행하지 않습니다.

## 2. 해결 방식과 AI의 역할

**원칙: 계산은 코드, 이해·검색·정리는 AI.** 금액과 수량은 LLM 출력에서 받지 않고 DB 값과 사용자 입력으로만 계산합니다.

```
지자체 선택 → 물건 목록 입력 → [AI] 품목 후보 매칭
→ [사람] 품목·규격 확정 → [코드] 수수료 계산
→ [AI] 배출 절차·체크리스트(근거 인용 + 서버 검증) → 결과 화면
→ 공유 링크 / 인쇄 / 복사 → (선택) 피드백
```

| 단계 | AI | 사람 | 코드 |
|---|---|---|---|
| 입력 해석 | 품목·수량 분리 보조 | 오타·누락 수정 | 줄 분리, 수량 추출 |
| 품목 매칭 | 후보 안에서 선택(닫힌 집합) | 품목·규격 확정 | 문자열 유사도 검색, 확실한 경우만 자동 확정 |
| 수수료 | 관여하지 않음 | 확인 | 단가 × 수량, 유료·무료·면제 구분 |
| 절차 안내 | 근거 문단 요약·체크리스트 | 전달 전 검토 | 근거 문단 선택, 인용·숫자 검증 |

**안전장치**
- 품목은 후보 목록 안에서만 선택합니다. 규격 단서가 없으면 AI가 규격을 임의로 고르지 않고 사용자에게 넘깁니다.
- 절차 답변은 근거 문단 번호를 인용해야 하고, 서버가 인용 문단의 실재와 숫자 일치를 검증합니다. 검증에 실패하면 1회 재시도 후 근거 원문 목록으로 낮춰 보여 줍니다.
- 근거가 없는 질문에는 "해당 내용은 안내문에서 확인되지 않습니다. 지자체에 문의하십시오."로 답합니다.
- 모든 화면에 기준일, 출처, 면책 문구를 표시합니다.
- LLM을 쓸 수 없거나 일일 상한을 넘으면 저하 모드로 동작합니다(검색 점수 기준 후보 표시, 자동 확정 없음).

## 3. 구조와 무료 운영 구성

| 구성요소 | 사용 | 비고 |
|---|---|---|
| 프런트 | React, TypeScript, Vite, Zustand, TanStack Query | GitHub Pages 배포 |
| 백엔드 | Python 3.13, FastAPI, Pydantic v2, SQLAlchemy | Render 무료 웹 서비스, 워커 1개 |
| DB | Supabase Postgres, pg_trgm, pgvector | 임베딩 열은 적재했으나 서비스 기본은 trigram |
| LLM | LangChain, Gemini(주) → Groq(폴백) | 모델명은 환경변수로 교체 |
| 임베딩 | Gemini embedding, 768차원 | 평가용으로 5개 지자체만 적재 |
| 자동화 | GitHub Actions(자동 시험, 프런트 배포, 10분 주기 서버 깨우기) | |

**데이터**
- 전국 대형폐기물 수수료 표준데이터(공공데이터포털): 144개 지자체, 품목·규격·단가(수준 2, 수수료만 제공).
- 성남시: 수수료 별표 PDF에서 추출한 품목·단가, 배출 절차 안내문(수준 1, 수수료와 절차 제공).
- 정제 원칙: 근거 없이 값을 채우거나 지우지 않습니다. 규격이 빈 행은 "규격 미기재"로 보존하고, 규격 정보가 없는 기관은 화면에 경고를 항상 표시합니다.

**화면 기능**: 지자체 검색·선택, 문장 입력과 품목 후보 확인, 품목 직접 검색, 견적 결과(지자체 수수료와 업체 작업비 분리), 공유 링크, 인쇄, 피드백, 절차 질문창(성남시만 답변), 예시 입력 버튼, 다크 모드 선택 버튼(선택은 이 브라우저에 저장), 지자체별 자료 이용 조건 표시(공공누리 유형, 확인일, 출처).

**API(8개)**: 헬스체크, 지자체 목록, 품목 직접 검색, 입력 분석·후보, 견적·절차 생성, 견적 조회(공유), 피드백 제출, 절차 질문.

**무료 운영의 제약과 대응**
- Render 무료 서버는 유휴 시 절전하므로 10분 주기 호출로 완화하고, 첫 화면에 대기 안내를 둡니다.
- 요청 제한(IP당 분당)과 일일 LLM 호출 상한은 서버 메모리에서 셉니다(재시작 시 초기화, 워커 확장 시 DB 방식으로 전환 필요).
- 견적은 30일 후 만료되며 정리 스크립트로 삭제합니다.

## 4. 평가 설계와 결과

**평가셋 v1**: 직접 작성한 매칭 64문항(일상 표현, 오타·띄어쓰기, 수량, 복수 규격, 타 지자체, 모호·미매칭)과 절차 16문항(답변 가능, 답변 불가, 수준 2 지자체). 개발용과 검증용으로 나누고, 검증용은 **최종 측정 1회에만** 사용합니다. 정답은 DB 행을 직접 확인해 지정했고, 정답 키는 `지자체코드|품목명|규격`입니다. 신뢰구간은 문항 단위 부트스트랩(1,000회)으로 계산합니다.

**평가 층위**
- L1 검색: recall@k, MRR, nDCG@5
- L2 매칭: 정확 확정률, 확정 오답률, 모호·미매칭 상태 구분, 수량 정확도
- L3 절차: 거절 정확도, 인용 유무, 근거 출처 적중, 필수 단어 포함, 충실도(판정 모델 3회 다수결)

**구성 비교(ablation)**

| 구성 | 검색 | LLM |
|---|---|---|
| C0 | trigram | 없음 |
| C1 | 벡터 | 없음 |
| C2 | 하이브리드(RRF) | 없음 |
| C3 | trigram | 후보 선택 |
| C4 | 하이브리드 | 후보 선택 |

### 4.2 검증용 최종 측정 (2026-11-17, 동결 기록 후 구성별 1회)

검증용 매칭은 19줄(확정해야 할 줄 6, 모호해야 할 줄 11, 미매칭 2)이고, 검색 지표는 정답이 있는 17줄로 계산합니다. 동결 기록(`eval/freeze.json`) 후 코드와 평가셋을 바꾸지 않았고, 구성마다 1회만 실행했습니다. 원본은 `eval/runs/20261117T0728_C0_test.json`, `...T0730_C2_test.json`, `...T0749_C3_test.json`입니다.

| 구성 | recall@1 (17줄, 95% CI) | 정확 확정 (6줄) | 확정 출력 중 오답 | 모호→확정 (11줄) | 미매칭 정확 (2줄) |
|---|---|---|---|---|---|
| C0 trigram | 0.82 (0.63~1.0) | 1/6 (0~0.50) | 0/1 | 0/11 | 1/2 |
| C2 하이브리드 | 1.0 (1.0~1.0) | 1/6 (0~0.50) | 0/1 | 0/11 | 0/2 |

- 지연(p50 / p95): C0 0.22초 / 0.92초, C2 0.90초 / 1.0초, C3 2.2초 / 7.6초(LLM 호출 포함).

- C4(하이브리드+LLM)의 검증용 측정은 **미실시**입니다. 개발용 측정만 있습니다(4.1절과 평가 일지).

### 4.3 해석

- **LLM이 정확 확정을 올렸습니다.** 개발용에서 C0 12/16 대비 C3 16/16이었고, 검증용에서도 C0·C2 1/6 대비 C3 6/6이었습니다(3회 반복 모두 같음). 확정 출력 중 오답은 모든 구성에서 0건입니다. 다만 확정해야 할 줄이 6줄뿐이어서 "항상 맞는다"는 근거가 되지 못하고, 건수로만 읽어야 합니다.
- **LLM 선택의 약점이 검증용에서 드러났습니다.** 모호해야 할 11줄 중 2줄을 C3가 자동 확정했습니다(3회 모두 같은 2줄). 정답으로 인정되는 후보 중 하나를 골랐으므로 확정 출력 오답은 0건이지만, 사용자에게 되묻는 것이 맞는 줄을 정해 버린 상태 오류입니다. 개발용에서는 0/25였으므로 개발용 조정이 검증용으로 완전히 일반화되지는 않았습니다.
- **검색 순위는 구성 간 차이를 구별하지 못했습니다.** 개발용 41줄에서 모든 구성이 recall@1 1.0에 닿아 천장 효과가 있었습니다. 검증용에서는 recall@1이 C0 0.82, C2 1.0으로 하이브리드가 높은 방향이지만 신뢰구간이 겹치고 17줄뿐이어서 벡터·하이브리드가 낫다고 결론 내리지 않습니다.
- **임베딩 구성의 첫 측정은 무효였고 재측정했습니다.** 무료 임베딩의 일일 한도(1,000건)를 넘어 11/16 낮의 일부 실행에서 질의 임베딩이 실패했고, 그 줄은 조용히 trigram으로 대체되어 순수한 값이 아니었습니다. 이를 발견한 뒤 실패 횟수를 결과 파일에 기록하게 했고, 한도가 풀린 11/16 17시 이후 개발용을 다시 측정했습니다(실패 0건 확인): C2 정확 확정 8/16(오답 0), C1 0/16, C4 16/16(오답 0). C1이 0인 것은 벡터 단독 후보의 점수를 0.7로 제한해 자동 확정 기준(0.9)에 닿지 못하게 한 설계의 결과이며 검색 능력이 0이라는 뜻이 아닙니다. 첫 측정의 무효 실행은 평가 일지에 정정으로 남겼습니다.
- **평가 과정에서 고친 결함**(근거를 일지에 남김): LLM의 규격 임의 선택(모호 25줄 중 10줄 확정 → 프롬프트 규칙으로 1줄), 프롬프트 예시가 평가 문항과 겹친 문제(예시 교체), 부분 문자열 일치의 자동 확정(옷장 → 비키니옷장, 기준 0.85 → 0.9), 충실도 판정에 200자로 잘린 근거를 넘긴 평가 오류(전문으로 수정, 6/7 → 7/7).

## 5. 한계와 정직한 보고

1. **평가셋이 작고 작성자가 1인입니다.** 검증용 매칭은 19줄 규모라 구성 간 작은 차이는 구별하지 못합니다.
2. **개발용 수치는 조정에 사용되었습니다.** 개발용 결과를 보고 프롬프트와 확정 기준을 바꿨으므로 일반화 성능이 아닙니다.
3. **지원 범위**: 절차 안내는 성남시 1곳만 제공합니다. 143개 지자체는 수수료만 제공하며, 규격이 없는 기관도 있습니다.
4. **모호한 입력의 자동 확정**: 검증용에서 C3가 모호해야 할 11줄 중 2줄을 확정했습니다(4.3절). 확정 전 사용자 확인 단계가 있어 화면에서는 선택을 바꿀 수 있지만, 자동 선택이 맞는 것처럼 보일 위험이 있습니다.
5. **미해결 매칭 한계**: 데이터에 없는 품목(개발용의 김치냉장고, 기타 잡동사니, 의류건조기)을 "후보 중 맞는 것 없음"으로 처리하지 못하고 모호로 표시합니다(개발용 3건, 검증용 미매칭 2줄 중 C3·C0은 1줄만 맞춤).
6. **임베딩 효과는 제한적으로만 확인**: 재측정 후 순수한 결과를 얻었지만, 검증용에서 C2는 정확 확정 수가 C0과 같고(1/6) recall@1만 높아졌으며 구간이 겹칩니다. C4의 검증용 측정은 실시하지 않았습니다.
7. **충실도 판정의 한계**: 판정 모델이 답변 모델과 같은 계열이라 자기 선호 편향이 있을 수 있어 사람 표본 확인이 필요합니다. 개발용 7건, 검증용 3건이라 구간이 넓습니다.
8. **업체 인터뷰는 미실시**입니다. 페르소나와 KPI는 가설이며, 공개 자료(지자체 안내, 보도)를 조사해 가설을 보강했습니다(`docs/research/interviews.md` 8절). 가상 설정을 실제 응답처럼 쓰지 않았고, 인터뷰 문항 중 업체의 실제 작업 방식에 관한 답은 얻지 못했습니다.
9. **무료 서비스 의존**: 모델 한도와 서버 절전, 모델명 변경에 영향을 받습니다. 모델명은 환경변수로 교체할 수 있습니다.
10. **데이터 이용 조건은 지자체마다 다르고, 확인된 곳은 성남시뿐입니다.** 확인 결과는 `docs/research/data_license_log.md`에 날짜와 근거(화면 표시, 주소)와 함께 있습니다. 이 보고서는 법률 자문이 아니며 지자체 페이지에 표시된 내용을 옮긴 것입니다.

| 지자체 | 확인한 표시 | 판정(2026-11-16 확인) |
|---|---|---|
| 성남시 | 공공누리 제1유형(출처표시) | 출처를 표시하면 상업적 이용·변경 가능. 화면 하단에 출처 표시 |
| 서울 강남구 | 공공누리 제4유형(출처표시+상업적 이용금지+변경금지) | 영리 목적 서비스에 맞지 않음 |
| 부산 해운대구 | 아이콘은 제4유형 모양, 옆 문구는 "출처표시"만 | 표시 불일치. 제한이 있는 것으로 취급 |
| 대구 수성구 | 대형폐기물 페이지의 표시 미확인(제4유형 가능성) | 미확인 |
| 경기 수원시 | 정책 페이지는 제1유형 원칙을 적었으나 대형폐기물 페이지에 표시 없음 | 미확인 |
| 그 밖의 139곳 | 포털 파일데이터별 이용허락범위 미확인 | 미확인 |

평가(연구·포트폴리오 목적)에는 전체 데이터를 사용했고, 공개 화면은 전국 지자체를 보여 줍니다. 이용 허락이 확인된 곳은 성남시뿐이므로, 화면에서 지자체를 선택하면 해당 지자체의 이용 조건과 확인일, 출처를 보여 주고 확인되지 않은 곳에는 "수수료는 참고용이며 영업 목적으로 쓰지 마십시오"를 표시합니다. 서버에는 노출할 지자체를 제한하는 환경변수(`ALLOWED_MUNICIPALITY_CODES`)가 있어 필요하면 공개 범위를 성남시로 즉시 줄일 수 있습니다. 각 지자체에 이용 허락을 문의한 결과는 아직 없습니다. 영리 목적으로 쓰려면 지자체별 확인이 먼저 필요합니다.
11. **법적·금액 책임**: 이 서비스의 금액은 안내용이며, 실제 수수료와 절차는 해당 지자체의 안내가 우선합니다(모든 화면에 면책 문구 표시).
12. **원본 데이터 문제의 보존**: 해운대구 "욕조 길이 1m 이상 2m 미만"이 원본에 12,000원과 9,000원 두 줄로 있으며, 근거 없이 지우지 않고 그대로 보존했습니다. 표준데이터와 내려받은 파일, DB가 일치함을 4개 지자체(강남·수원·수성·해운대)에서 확인했습니다(차이 0건).

## 6. 운영·보안·개인정보

- 키(Gemini, Groq, DB)는 저장소에 올리지 않고 `backend/.env`와 Render 환경변수에만 둡니다. `.env.example`만 커밋합니다.
- 개인정보(이름, 연락처, 주소)는 수집하지 않으며 입력창과 피드백 창에 입력 금지 안내를 표시합니다.
- 오류 응답 형식을 통일했고(코드·메시지·상세), 분당 요청 제한(429, `Retry-After`)과 일일 호출 상한을 둡니다.
- 견적은 생성 후 30일에 만료되고 `scripts/cleanup_expired.py`로 정리합니다. 피드백은 견적과 함께 삭제됩니다.
- 피드백은 `scripts/export_feedback.py`로 평가셋 보강 후보로 내보내며, 평가셋 반영은 사람이 확인하고 새 버전으로 기록합니다.

## 7. 앞으로의 개선

우선순위 순입니다.
1. 업체 인터뷰로 페르소나·KPI 보정, 실제 입력 문장으로 평가셋 확대(v2).
2. "후보 중 맞는 것 없음"을 미매칭으로 처리해 데이터에 없는 품목의 오분류 줄이기.
3. 검증용 평가셋을 늘리고(v2) 임베딩 구성을 다시 측정해, 효과가 확인될 때만 서비스에 적용.
4. 요청 제한·일일 상한을 DB 카운터로 전환(워커 확장 대비).
5. 절차 안내 제공 지자체 확대, 그리고 지자체별 이용 조건 문의·확인(강남·해운대·수성·수원 우선). 확인된 곳만 `ALLOWED_MUNICIPALITY_CODES`에 추가.
6. 모호한 입력의 자동 확정을 줄이기 위한 확정 기준 재검토(검증용 2건 사례를 평가셋 v2에 반영).
7. 카카오톡 채널 연동(도입 전략 A).
