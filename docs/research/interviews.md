# 업체 인터뷰 (가상 설정 + 질문지)

> **이 문서의 "가상 응답"은 실제 인터뷰 결과가 아니라 가설입니다.** 페르소나(PRD 3절)와 KPI를 구체화하고 인터뷰 때 무엇을 확인할지 정하기 위한 시나리오입니다. 실제 인터뷰를 하면 아래 기록 서식으로 **추가**하고, 가상 설정은 수정하지 않습니다. 근거로 인용할 때는 반드시 "가설"이라고 표기합니다.

## 1. 인터뷰 대상 (실제 섭외 기준)
| 구분 | 기준 |
|---|---|
| 대상 | 성남시 및 인근에서 이사·정리·폐기물 처리를 하는 업체의 견적 담당자(대표, 실장) |
| 인원 | 2~3명, 1인당 5~10분(전화) |
| 섭외 | 사용자가 직접 연락처를 확보 (연락처 정보는 이 문서에 기록하지 않음) |
| 사전 안내 | 개인정보와 고객 정보는 말씀하지 않도록 안내 |

## 2. 질문지
1. 고객 1건의 대형폐기물 견적을 내는 데 보통 얼마나 걸립니까? 어떤 순서로 하십니까?
2. 지자체 수수료는 어떻게 확인하십니까? (사이트, 전화, 기억 등)
3. 고객이 말하는 물건 이름과 공식 품목명이 달라 곤란했던 경우가 있습니까?
4. 수수료를 잘못 안내해서 문제가 생긴 적이 있습니까?
5. 한 달에 대략 몇 건을 처리하십니까?
6. 지자체 수수료와 업체 작업비를 구분해 고객에게 설명하십니까?
7. 이런 도구가 있다면 어떤 화면과 결과물이 필요합니까? (공유 링크, 인쇄 등)
8. 이용 비용(월 구독 또는 건별)이 있다면 어느 정도까지 고려하시겠습니까? (금액은 유도하지 않고 열린 질문으로)

## 3. 가상 설정 (가설, 실제 인터뷰 아님)
| 항목 | 가상 설정 |
|---|---|
| 인물 | 박정훈 실장(PRD 3.1) 유형: 이사·정리 업체 견적 담당 |
| 업무 방식 | 전화·문자로 고객 물건을 들은 뒤 사이트나 기억으로 수수료를 찾아 합산 |
| 불편 | 품목명 표기 차이로 찾는 데 시간이 걸림, 규격 선택 실수 우려, 고객에게 근거를 보여 주기 어려움 |
| 기대 | 후보 제시 + 확정, 지자체 수수료와 작업비 분리 표시, 링크 공유 |
| 우려 | AI가 틀린 금액을 단정하는 것 |

## 4. 가설 검증 연결
| 가설 | 확인 질문 | 판단 기준 |
|---|---|---|
| H1 조회 시간 단축 | 1, 2, 3 | 현재 소요 시간 확인 후 단축률 목표 설정 |
| H2 후보 + 확인 구조 | 4, 7 | 확인 단계를 불편이 아니라 안전장치로 보는지 |
| H3 수수료·작업비 분리 | 6 | 고객 설명에 쓸 수 있다고 응답 |
| H4 지불 의사 | 8 | 지불 의사 표현 여부 |

## 6. 통화 진행 대본 (2026-11-16 추가, 1인당 5~10분)
**목적**: 가설(H1~H4)의 실제 응답을 얻는 것입니다. 제품을 설득하려 하지 않고 업무 방식을 듣습니다.

1. 시작(30초): 대형폐기물 견적을 쉽게 내는 도구를 개인 프로젝트로 만들고 있어 업무 방식을 5~10분 여쭙고 싶다고 밝힙니다. 응답은 익명으로만 기록하며, 고객 정보와 개인정보는 말씀하지 않으셔도 된다고 안내합니다. 녹음하지 않고 메모만 한다고 안내합니다.
2. 질문(5~7분): 2절의 질문을 1번부터 순서대로 묻습니다. 답이 짧으면 "최근 한 건을 예로 들어 주시겠습니까"로 구체화합니다. 8번(비용)은 금액을 먼저 제시하지 않습니다.
3. 시연(선택, 2분): 허락하시면 배포 주소(https://ksunnyoo.github.io/planforlargewaste/)를 문자로 보내 직접 써 보시게 하고, 틀린 점이나 부족한 점을 말씀해 달라고 요청합니다. 결과 화면의 "결과가 다르면 알려 주십시오" 버튼 사용법도 알립니다.
4. 마무리(30초): 감사 인사와 함께 후속 연락 여부를 묻습니다. 연락처는 이 문서에 기록하지 않습니다.

**기록 요령**: 통화 직후 5절 표에 한 줄을 추가합니다. 응답이 가설과 달랐던 점을 "페르소나·KPI 보정" 칸에 반드시 적습니다. 가설을 지지하는 응답만 골라 쓰지 않습니다.

**섭외가 어려울 때**: 2명 미만이면 인터뷰 결과가 아니라 "탐색적 확인 N건"으로 표기하고, 3절의 가상 설정을 실제 응답처럼 쓰지 않습니다.

## 7. 예상 응답 (가설, 2026-11-16 추가)
> **이 절의 내용은 실제 응답이 아니라 Claude가 업무 구조에서 추정한 가설입니다.** 5절 실제 기록 표에 옮기지 않고, 보고서의 근거로 쓰지 않습니다. 실제 통화에서 아래와 다른 응답이 나오면 5절에 그대로 기록하고 PRD의 페르소나·KPI 보정에 반영합니다.

| 질문 | 예상 응답(가설) | 맞다면 시사점 | 통화 때 확인할 점 |
|---|---|---|---|
| 1. 견적 소요 시간·순서 | 고객이 보낸 목록을 보며 품목마다 지자체 사이트나 이전 견적표에서 단가를 찾아 합산합니다. 품목이 많으면 시간이 걸립니다 | 입력 한 번에 목록을 처리하는 가치가 있음 | 실제 건당 시간, 목록 길이, 합산 방식(엑셀·수기) |
| 2. 수수료 확인 방법 | 지자체 사이트, 전화 문의, 이전에 정리한 표를 함께 씁니다 | 최신 기준일과 출처 표시가 중요함 | 어느 방법을 주로 쓰는지, 표를 얼마나 자주 갱신하는지 |
| 3. 품목명 불일치 | 고객이 쓰는 표현과 공식 품목명이 달라 찾기 어려운 경우가 있습니다 | 후보 제시와 사용자 확정 구조가 맞음 | 곤란했던 실제 품목 예(평가셋 보강에 활용) |
| 4. 안내 오류 경험 | 규격을 잘못 골라 금액이 달라진 경험이 있을 수 있습니다 | 규격 확인 단계를 안전장치로 받아들일 가능성 | 오류의 원인(규격, 지역, 기준 변경)과 대응 방식 |
| 5. 월 처리 건수 | 업체 규모에 따라 크게 다릅니다 | 사용 빈도 가정은 업체별로 다름 | 월 건수 범위만(정확한 수치는 요구하지 않음) |
| 6. 수수료·작업비 구분 | 고객에게 합계로 안내하는 경우가 많고, 구분해 설명하는 업체도 있습니다 | 분리 표시가 설명용으로 쓰일 수 있음 | 고객이 구분을 요구하는지, 합계만 원하는지 |
| 7. 필요한 화면·결과물 | 카카오톡이나 문자로 보낼 수 있는 요약과 인쇄 가능한 견적서를 선호할 것입니다 | 링크 공유·내용 복사·인쇄 기능과 일치 | 주로 쓰는 전달 채널 |
| 8. 비용 의향 | 응답이 갈리거나 무료 도구를 선호할 것입니다 | 지불 의사는 가설로 남김 | 금액을 먼저 제시하지 않고 열린 질문으로 확인 |

**활용 원칙**: 위 표는 통화 준비용 체크 목록입니다. 가설과 같은 응답이 나와도 "가설이 지지되었다"는 표시는 실제 응답 기록에만 남깁니다.

## 8. 공개 자료 기반 보조 조사 (2026-11-16 추가, 인터뷰를 대체하지 않음)

### 한계
- 모두 시민 대상 안내이거나 기사이며, 이사·정리 업체 견적 담당자의 업무 방식(소요 시간, 월 건수, 지불 의사)은 공개 자료로 확인하지 못했습니다. 이 항목은 질문 1, 5, 8의 답이 없는 상태로 남습니다.
- 최종 보고서에는 "업체 인터뷰 미실시, 공개 자료와 가설로 대체"로 적고, 요구사항을 검증했다고 쓰지 않습니다.
